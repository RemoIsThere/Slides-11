What Is Inheritance?

Inheritance allows a new class to acquire accessible members and behavior from an existing class.

Vehicle
↓
Car
↓
ElectricCar

Superclass

General class containing common state and behavior. 

class Vehicle {
    String brand;

    void start() {
        System.out.println("Vehicle starts");
    }
}

Subclass

More specialized class that extends the superclass. 

class Car
        extends Vehicle {

    void drive() {
        System.out.println("Car drives");
    }
}
04 / 40

IS-A vs HAS-A

IS-A → Inheritance

A Car is a Vehicle. 

class Car
        extends Vehicle { }
Use inheritance when the subclass truly represents a specialized form of the superclass.

HAS-A → Composition

A Car has an Engine. 

class Car {
    Engine engine;
}
Do not use inheritance simply because code reuse is convenient.
Which relation is represented by class Dog extends Animal?
Correct — Dog IS-A Animal.

        c.display();
    }
}

extends

Connects a class to one direct superclass.

Reuse

Subclass can use accessible inherited members.

Specialize

Multiple Inheritance

A class inheriting from two concrete classes is not supported in Java. 

// Not allowed in Java

class A {
}

class B {
}

class C
        extends A, B {
}
Why? If both parents expose the same method, Java would face ambiguity about which implementation should be inherited.
Does Java allow a class to directly extend two classes?
Correct. Java uses interfaces to support multiple inheritance of type.

Multiple Inheritance via Interfaces

A Java class can implement multiple interfaces. 

interface Printable {
    void print();
}

interface Scannable {
    void scan();
}

class Machine
        implements Printable, Scannable {

    public void print() {
        System.out.println("Printing");
    }

    public void scan() {
        System.out.println("Scanning");
    }
}
One class can implement several contracts while still extending only one class.

The super Keyword

1. Parent field

Access a hidden superclass field.

2. Parent method

Call an overridden superclass method.

3. Parent constructor

Invoke the superclass constructor. 

class Parent {
    int x = 10;

    void show() {
        System.out.println("Parent show");
    }
}

class Child extends Parent {
    int x = 20;

    void show() {
        System.out.println(super.x);
        super.show();
    }
}

super() and Constructors

class Person {
    String name;

    Person(String name) {
        this.name = name;
    }
}

class Student
        extends Person {

    int rollNo;

    Student(String name, int rollNo) {
        super(name);
        this.rollNo = rollNo;
    }
}
super(...) must be the first statement in a constructor when it is explicitly used.
Which constructor runs first when a Student object is created?
The superclass constructor executes before the subclass constructor body.

Method Overriding

A subclass provides a specialized implementation of an inherited instance method with the same signature. 

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog
        extends Animal {

    @Override
    void sound() {
        System.out.println("Bark");
    }
}

Signature

Same method name and parameter list.

@Override

Lets the compiler verify that the method really overrides an inherited method.

18 / 40

Method Overloading

Same method name, different parameter list. 

class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}
Overloading is resolved using the method signature and compile-time type information.
Is changing only the return type enough to overload a method?
No. Return type alone does not distinguish overloaded methods.

Upcasting

Treat a subclass object as a superclass reference. 

Dog dog = new Dog();

Animal animal = dog;

Safe

Every Dog is an Animal, so the conversion is valid.

Polymorphic

The Animal reference can still invoke overridden Dog instance methods.

Upcasting is usually implicit.
22 / 40

Downcasting

Convert a superclass reference back to a subclass reference when the actual object really is that subtype. 

Animal a = new Dog();

Dog d = (Dog) a;

d.fetch();
Downcasting is explicit. The cast does not change the object. It only changes how the reference views it.
If the actual object is not a Dog, the cast can throw ClassCastException.
23 / 40

instanceof

Use instanceof to test whether an object is compatible with a specific reference type. 

Animal a = new Dog();

if (a instanceof Dog) {
    Dog d = (Dog) a;
    d.fetch();
}
For Animal a = new Dog();, what is the result of a instanceof Dog?
true, because the actual object is a Dog.
Modern Java can also use pattern matching for instanceof, but the classic cast form is essential for understanding the underlying concept.

Shape Hierarchy

abstract class Shape {
    abstract double area();
}

class Circle
        extends Shape {

    double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    double area() {
        return Math.PI * radius * radius;
    }
}

class Rectangle
        extends Shape {

    double width;
    double height;

    Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    double area() {
        return width * height;
    }
}

Shape Polymorphism

Shape[] shapes = {
    new Circle(5),
    new Rectangle(4, 6)
};

for (Shape s : shapes) {
    System.out.println(s.area());
}

Compile time

The compiler sees Shape as the reference type.

Runtime

The overridden area() belonging to Circle or Rectangle executes.

This is polymorphism doing useful work: the loop does not need separate logic for every concrete shape.

Abstract Classes + Inheritance

Abstract classes are useful when related subclasses share state or common implemented behavior but must provide their own specialized implementation. 

abstract class Employee {

    String name;

    abstract double calculateSalary();

    void login() {
        System.out.println("Employee login");
    }
}

class Developer
        extends Employee {

    double calculateSalary() {
        return 60000;
    }
}
An abstract class cannot be instantiated directly, but it can be used as a polymorphic reference type.

Common Mistakes

1. Confusing overloading with overriding

Different parameters = overloading. Same inherited signature = overriding.

2. Assuming reference type controls runtime method

For overridden instance methods, the actual object matters.

3. Unsafe downcasting

A cast cannot turn one object into another type.

4. Misusing inheritance

Use composition where the relationship is HAS-A.

The compiler can prevent many mistakes. It cannot rescue poor object-modeling decisions from bad design.

Debugging Lab

class Animal { }

class Cat extends Animal { }

class Dog extends Animal { }

Animal a = new Cat();

Dog d = (Dog) a;
What happens on the last line?
The actual object is Cat, not Dog. The downcast therefore fails at runtime with ClassCastException.
Safer pattern: if (a instanceof Dog) { ... }
