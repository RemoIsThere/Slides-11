🗄️ What is DBMS?
  • Database Management System — software for creating, managing, and querying databases
  • Examples — MySQL, PostgreSQL, Oracle, SQL Server, MongoDB
  • Types — Relational (RDBMS), NoSQL, NewSQL
  • Purpose — efficient data storage, retrieval, security, and integrity
-- Data is organized in tables (relations) CREATE TABLE employees ( id INT PRIMARY KEY, name VARCHAR(100), salary DECIMAL(10,2) );
📐 ER Diagrams
  • Entity — object or concept (e.g., Student, Course)
  • Attribute — properties of an entity (e.g., name, age)
  • Relationship — association between entities (e.g., Enrolls)
  • Cardinality — 1:1, 1:N, M:N
💡 Key: ER diagrams are the blueprint for database design.
📊 Normalization
  • 1NF — atomic values, no repeating groups
  • 2NF — 1NF + no partial dependency on composite key
  • 3NF — 2NF + no transitive dependency
  • BCNF — 3NF + every determinant is a candidate key
  • Purpose — eliminate redundancy, avoid anomalies
💡 Key: Higher normal forms = less redundancy, more tables.
📊 Normalization Example
Before (Unnormalized)
StudentID, Name, Course1, Course2, Course3
1NF
StudentID, Name, Course (atomic, no repeating groups)
2NF
Student(StudentID, Name) + Enrollment(StudentID, CourseID)
3NF
Student(StudentID, Name, DeptID) + Department(DeptID, DeptName)
🔒 ACID Properties
Atomicity
All or nothing
Transaction completes fully or not at all
Consistency
Valid state
Database remains in consistent state
Isolation
Concurrent transactions
Transactions don't interfere with each other
Durability
Persistent
Committed changes survive system failure
🔄 Transactions
  • Transaction — sequence of operations treated as a single unit
  • BEGIN — start transaction
  • COMMIT — save changes permanently
  • ROLLBACK — undo all changes
  • SAVEPOINT — partial rollback
BEGIN TRANSACTION; UPDATE accounts SET balance = balance - 100 WHERE id = 1; UPDATE accounts SET balance = balance + 100 WHERE id = 2; COMMIT; -- or ROLLBACK if any error
🔍 Indexing
  • Purpose — speed up data retrieval (like a book's index)
  • Types — B‑Tree, Hash, Bitmap, Full‑text
  • Trade‑off — faster reads, slower writes (index maintenance)
  • When to use — columns used in WHERE, JOIN, ORDER BY
CREATE INDEX idx_employee_name ON employees(name); -- Query becomes faster on name column SELECT * FROM employees WHERE name = 'John';

🏗️ DDL Commands
-- CREATE table CREATE TABLE employees ( id INT PRIMARY KEY, name VARCHAR(100) NOT NULL, salary DECIMAL(10,2), dept_id INT ); -- ALTER table ALTER TABLE employees ADD COLUMN email VARCHAR(255); -- DROP table DROP TABLE employees; -- TRUNCATE (removes all data, keeps structure) TRUNCATE TABLE employees;
✏️ DML Commands
-- INSERT INSERT INTO employees (id, name, salary, dept_id) VALUES (1, 'Alice', 50000, 10); -- SELECT SELECT * FROM employees WHERE salary > 40000; -- UPDATE UPDATE employees SET salary = salary * 1.10 WHERE dept_id = 10; -- DELETE DELETE FROM employees WHERE id = 1;
🔍 SELECT Clauses
-- ORDER BY (sorting) SELECT * FROM employees ORDER BY salary DESC; -- GROUP BY + HAVING SELECT dept_id, AVG(salary) AS avg_salary FROM employees GROUP BY dept_id HAVING AVG(salary) > 50000; -- LIMIT / TOP SELECT * FROM employees ORDER BY salary DESC LIMIT 5; -- DISTINCT SELECT DISTINCT dept_id FROM employees;
🔗 JOINs
INNER JOIN
Only matching rows
Most common JOIN
LEFT JOIN
All left rows + matches
NULL for non‑matching right
RIGHT JOIN
All right rows + matches
NULL for non‑matching left
FULL JOIN
All rows from both
NULL where no match
🔗 JOIN Examples
-- Tables: employees(id, name, dept_id), departments(id, name) -- INNER JOIN: employees with department SELECT e.name, d.name AS dept_name FROM employees e INNER JOIN departments d ON e.dept_id = d.id; -- LEFT JOIN: all employees, even without department SELECT e.name, d.name AS dept_name FROM employees e LEFT JOIN departments d ON e.dept_id = d.id; -- Self‑join: employees and their managers SELECT e1.name AS employee, e2.name AS manager FROM employees e1 LEFT JOIN employees e2 ON e1.manager_id = e2.id;
📦 Subqueries
  • Subquery — query inside another query (nested)
  • Types — scalar, row, table, correlated
  • Operators — =, >, IN, EXISTS, ANY, ALL
-- Find employees earning more than average SELECT name, salary FROM employees WHERE salary > (SELECT AVG(salary) FROM employees); -- Find departments with no employees SELECT * FROM departments WHERE id NOT IN (SELECT DISTINCT dept_id FROM employees); -- Correlated subquery SELECT e1.name, e1.salary FROM employees e1 WHERE salary > (SELECT AVG(salary) FROM employees e2 WHERE e2.dept_id = e1.dept_id);
🪟 Window Functions
  • ROW_NUMBER() — sequential number per partition
  • RANK() / DENSE_RANK() — ranking with/without gaps
  • LAG() / LEAD() — access previous/next row
  • SUM() OVER — cumulative sums
-- Rank employees by salary within each department SELECT name, dept_id, salary, RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank FROM employees; -- Cumulative salary by department SELECT name, dept_id, salary, SUM(salary) OVER (PARTITION BY dept_id ORDER BY name) AS cumulative FROM employees; -- Previous employee's salary SELECT name, salary, LAG(salary, 1) OVER (ORDER BY name) AS prev_salary FROM employees;
👁️ Views
  • View — virtual table based on a SELECT query
  • Benefits — security, simplicity, data abstraction
  • Materialized View — stores data physically (faster reads)
CREATE VIEW high_earners AS SELECT name, salary, dept_id FROM employees WHERE salary > 60000; -- Query the view like a table SELECT * FROM high_earners ORDER BY salary DESC; -- Drop view DROP VIEW high_earners;
⚙️ Stored Procedures
  • Procedure — reusable SQL code with parameters
  • Benefits — performance, security, modularity
  • Can contain — SELECT, UPDATE, INSERT, DELETE, logic
CREATE PROCEDURE give_raise(IN dept_id INT, IN percent DECIMAL) BEGIN UPDATE employees SET salary = salary * (1 + percent / 100) WHERE dept_id = dept_id; END; -- Call the procedure CALL give_raise(10, 5.0); -- 5% raise for dept 10
⚡ Triggers
  • Trigger — automatically executes on INSERT, UPDATE, DELETE
  • Timing — BEFORE or AFTER the event
  • Use cases — auditing, validation, cascading updates
CREATE TRIGGER audit_salary_change AFTER UPDATE ON employees FOR EACH ROW BEGIN INSERT INTO salary_audit(employee_id, old_salary, new_salary, changed_at) VALUES (OLD.id, OLD.salary, NEW.salary, NOW()); END; -- Now any salary update logs the change UPDATE employees SET salary = 55000 WHERE id = 1;

📐 Q1 — ER Diagram Design
Easy Class

Problem: Design an ER diagram for a library management system.

Entities: Book, Member, Loan
Relationships: Member borrows Book (M:N with loan date, due date)
Attributes: Book(ISBN, title, author, year), Member(id, name, email)
Cardinality: Member (1) → Loan (M) → Book (1)
💡 Key: Identify entities, attributes, and relationships first.

Medium Class

Problem: Normalize the following table to 3NF.

-- Table: Order(OrderID, CustomerID, CustomerName, ProductID, ProductName, Quantity, Price) -- FD: CustomerID → CustomerName, ProductID → ProductName, OrderID → CustomerID, ProductID, Quantity -- Solution: -- 1. 🔍 Q3 — Basic SQL Queries
Easy Class

Problem: Write SQL queries for the following tasks.

-- 1. Find all employees with salary > 50000 SELECT * FROM employees WHERE salary > 50000; -- 2. Count employees in each department SELECT dept_id, COUNT(*) AS count FROM employees GROUP BY dept_id; -- 3. Find the highest salary SELECT MAX(salary) FROM employees; -- 4. Find employees whose name starts with 'A' SELECT * FROM employees WHERE name LIKE 'A%';
🔗 Q4 — JOINs & Subqueries
Medium Class

Problem: Write queries using JOINs and subqueries.

-- 1. List employees with their department names (INNER JOIN) SELECT e.name, d.name AS dept_name FROM employees e INNER JOIN departments d ON e.dept_id = d.id; -- 2. Find departments with no employees (LEFT JOIN + NULL) SELECT d.* FROM departments d LEFT JOIN employees e ON d.id = e.dept_id WHERE e.id IS NULL; -- 3. Find employees earning more than department average (correlated subquery) SELECT e1.name, e1.salary, e1.dept_id FROM employees e1 WHERE salary > (SELECT AVG(salary) FROM employees e2 WHERE e2.dept_id = e1.dept_id);
🪟 Q5 — Window Functions
Medium Homework

Problem: Write queries using window functions.

-- 1. Rank employees by salary overall SELECT name, salary, RANK() OVER (ORDER BY salary DESC) AS rank FROM employees; -- 2. Running total of salaries by department SELECT name, dept_id, salary, SUM(salary) OVER (PARTITION BY dept_id ORDER BY name) AS running_total FROM employees; -- 3. Salary difference from previous employee SELECT name, salary, salary - LAG(salary, 1, 0) OVER (ORDER BY name) AS diff_from_prev FROM employees; -- 4. Top 3 earners per department SELECT name, dept_id, salary, rank FROM ( SELECT *, RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank FROM employees ) t WHERE rank <= 3;
⚙️ Q6 — Stored Procedure
Hard Homework

Problem: Create a stored procedure to transfer funds between accounts.

CREATE PROCEDURE transfer_funds( IN from_account INT, IN to_account INT, IN amount DECIMAL(10,2) ) BEGIN DECLARE from_balance DECIMAL(10,2); START TRANSACTION; SELECT balance INTO from_balance FROM accounts WHERE id = from_account; IF from_balance < amount THEN ROLLBACK; SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Insufficient funds'; ELSE UPDATE accounts SET balance = balance - amount WHERE id = from_account; UPDATE accounts SET balance = balance + amount WHERE id = to_account; COMMIT; END IF; END; -- Call: CALL transfer_funds(1, 2, 100.00);
