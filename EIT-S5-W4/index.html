01

Classes and Objects

A class is the fundamental unit of design in Java. An object is a concrete instance of that design. Everything else in OOP builds on this foundation.

Classes and Objects

What Is a Class?

Definition

A class is a blueprint or template that defines the structure and behaviour of a category of objects. It specifies:

  • What data an object will hold (fields).
  • What operations an object can perform (methods).
  • How objects are created (constructors).

Reference Type

A class is a reference type. Variables of a class type hold references to objects, not the objects themselves.

Class Declaration

accessModifier class ClassName {
    // fields (state)
    // constructors
    // methods (behaviour)
}

Minimal Example

public class Student {
    String name;
    int rollNo;
}

This declares a class with two fields. No objects exist yet — the class is only a blueprint.

Naming Rules

  • Must be a valid Java identifier.
  • Cannot be a keyword.
  • Convention: PascalCase.
  • Public class name must match file name.

Example — Full Class Skeleton

public class Student {
    // 1. Static variable
    private static int count = 0;

    // 2. Instance variables
    private String name;
    private int rollNo;

    // 3. Static block
    static {
        System.out.println("Class loaded");
    }

    // 4. Constructor
    public Student(String name, int rollNo) {
        this.name = name;
        this.rollNo = rollNo;
        count++;
    }

    // 5. Instance method
    public void display() {
        System.out.println(name + " | " + rollNo);
    }

    // 6. Static method
    public static int getCount() {
        return count;
    }
}
Classes and Objects

What Is an Object?

Definition

An object is a specific instance of a class — a concrete entity created in memory with its own copy of the class's fields.

Creating Objects

Student s1 = new Student();
s1.name = "Alice";
s1.rollNo = 101;

Student s2 = new Student();
s2.name = "Bob";
s2.rollNo = 102;

System.out.println(s1.name); // Alice
System.out.println(s2.name); // Bob

What Happens at new

  1. Memory is allocated on the heap for the object.
  2. Fields are initialized to default values.
  3. The constructor runs.
  4. A reference to the new object is returned.

Each Object Has Its Own Fields

s1 and s2 are distinct objects. Changing s1.name does not affect s2.name.

Common Mistake

Student s;
s.name = "Alice";
// compile error: s might not be initialized

You must create an object with new before using it.

Classes and Objects

Object References and null

Reference Semantics

Variables of a class type hold references, not the objects themselves. Assigning one reference to another does not copy the object.

Student a = new Student();
Student b = a;         // b points to same object
b.name = "Zara";

System.out.println(a.name); // Zara

Visual Representation

a ──┐
    ↓
  [Student object]
    ↑
b ──┘

Both a and b reference the same object on the heap.

Null Reference

Student s = null;
s.display();
// NullPointerException

A null reference does not point to any object. Calling a method on it throws NullPointerException.

Comparing References

Student a = new Student();
Student b = new Student();

System.out.println(a == b); // false — different objects

Student c = a;
System.out.println(a == c); // true — same object

== compares references, not field values. This will be revisited in the object identity section.

Garbage Collection

When no references point to an object, it becomes eligible for garbage collection. The JVM reclaims the memory automatically.

Complete Example — Student

    private int rollNo;

02

Instance vs Static Variables

Not all state belongs to individual objects. Some state belongs to the class itself. Java distinguishes these with the static keyword.

Instance vs Static

Instance Variables

Definition

Instance variables are fields declared without static. Each object gets its own copy.

public class Student {
    String name;    // instance variable
    int rollNo;      // instance variable
}

Per-Object Storage

Student a = new Student();
Student b = new Student();

a.name = "Alice";
b.name = "Bob";

System.out.println(a.name); // Alice
System.out.println(b.name); // Bob

Key Characteristics

  • Stored on the heap as part of the object.
  • One copy per object.
  • Initialized to default values.
  • Accessed through this or an object reference.
  • Lifetime = lifetime of the object.

When to Use Instance Variables

  • The value describes a specific object.
  • Different objects should be able to hold different values.
  • The value changes as the object's state changes.

Encapsulation Best Practice

Make instance variables private. Expose behaviour through public methods rather than allowing direct field access.

Instance vs Static

Static Variables

Definition

Static variables are fields declared with static. There is exactly one copy shared by all objects of the class.

public class Student {
    String name;
    static int count = 0;  // shared

    public Student(String name) {
        this.name = name;
        count++;
    }
}

Usage

Student a = new Student("Alice");
Student b = new Student("Bob");
Student c = new Student("Charlie");

System.out.println(Student.count); // 3

Key Characteristics

  • Stored in the class area of memory.
  • One copy per class.
  • Initialized to default values when the class is loaded.
  • Accessed through the class name (preferred).
  • Lifetime = lifetime of the class.

Common Uses

  • Counting instances of a class.
  • Shared configuration values.
  • Constants (static final).
  • Caches shared across all objects.

Thread Safety Warning

Static variables are not thread-safe by default. Concurrent modification can corrupt shared state. We will cover synchronization in a later unit.

03

Encapsulation

Encapsulation is the practice of hiding internal state and exposing only what is necessary through a controlled interface. It is the foundation of robust class design.

Encapsulation

What Is Encapsulation?

Definition

Encapsulation is the practice of hiding the internal state of an object and exposing only what is necessary through a controlled interface. It is one of the four pillars of object-oriented programming.

How Java Supports It

  • Access modifiers: private, public, protected, default.
  • Getters and setters: Controlled access to fields.
  • Packages: Package-private access for internal collaboration.

The Encapsulation Pattern

  1. Declare fields as private.
  2. Provide public getters and setters as needed.
  3. Validate inputs in setters and constructors.
  4. Omit setters for fields that should not change.
  5. Use private for helper methods.

Data Hiding vs Encapsulation

  • Data hiding: making fields private.
  • Encapsulation: the broader practice of bundling data and behaviour, controlling access, and exposing a well-designed interface.
Encapsulation

Encapsulation in Practice — BankAccount

BankAccount.java

public class BankAccount {
    private final String accountNumber;
    private String holderName;
    private double balance;

    public BankAccount(String accountNumber,
                       String holderName,
                       double initialBalance) {
        if (accountNumber == null
            || accountNumber.isEmpty()) {
            throw new IllegalArgumentException(
                "Account number required");
        }
        if (initialBalance < 0) {
            throw new IllegalArgumentException(
                "Initial balance cannot be negative");
        }
        this.accountNumber = accountNumber;
        this.holderName = holderName;
        this.balance = initialBalance;
    }

    public String getAccountNumber() {
        return accountNumber;
    }

    public double getBalance() {
        return balance;
    }

    public void setHolderName(String holderName) {
        if (holderName != null
            && !holderName.isEmpty()) {
            this.holderName = holderName;
        }
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Deposit must be positive");
        }
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Withdrawal must be positive");
        }
        if (amount > balance) {
            throw new IllegalStateException(
                "Insufficient balance");
        }
        balance -= amount;
    }
}

What This Demonstrates

  • Fields are private — no direct access from outside.
  • Constructor validates inputs.
  • Setters validate before assigning.
  • Methods enforce business rules (no negative balance).
  • accountNumber is final — read-only after construction.

If Fields Were Public

BankAccount acc = new BankAccount(...);
acc.balance = -999999;
// No validation — invariant broken

Encapsulation prevents this class of bug entirely.

Usage

BankAccount acc = new BankAccount(
    "ACC1001", "Alice", 1000);

acc.deposit(500);
acc.withdraw(200);
System.out.println(acc.getBalance());
// 1300.0
Encapsulation

Getters and Setters

Naming Conventions

Field TypeGetterSetter
String namegetName()setName(String)
int agegetAge()setAge(int)
boolean activeisActive()setActive(boolean)
double gpagetGpa()setGpa(double)

Read-Only Property

Provide only a getter for fields that should not change after construction.

public class Student {
    private final int rollNo;

    public Student(int rollNo) {
        this.rollNo = rollNo;
    }

    public int getRollNo() {
        return rollNo;
    }
    // no setter
}

Setter With Validation

public class Student {
    private double gpa;

    public double getGpa() {
        return gpa;
    }

    public void setGpa(double gpa) {
        if (gpa >= 0 && gpa <= 10) {
            this.gpa = gpa;
        } else {
            throw new IllegalArgumentException(
                "GPA must be between 0 and 10");
        }
    }
}

Write-Only Property (Rare)

public class User {
    private String password;

    public void setPassword(String password) {
        this.password = password;
    }
    // no getter
}

Typically used for sensitive fields like passwords.

Encapsulation

Benefits of Encapsulation

Data Hiding

Internal state cannot be modified arbitrarily. Clients must go through the public interface.

Validation

Setters and constructors can reject invalid input before it corrupts state.

Invariants

The class can enforce rules such as "balance never negative" or "name never empty".

Flexibility

Internal representation can change without breaking client code, as long as the public methods stay the same.

Maintainability

Changes are localized to the class. Bugs are easier to trace and fix.

Security

The attack surface is limited to the public methods. Private state cannot be tampered with.

Rule of Thumb

Start with the most restrictive access that works. Widen only when a concrete need appears. Every public method is a contract you must maintain.

Constructors

A constructor is a special method that runs when an object is created. It is how you guarantee an object starts in a valid state.

Constructors

What Is a Constructor?

Definition

A constructor is a special method invoked automatically when an object is created with new. Its purpose is to initialize the new object's fields.

Syntax

public class Student {
    String name;

    // constructor
    public Student() {
        name = "Unknown";
    }
}

Rules

  1. Name must match the class name exactly.
  2. No return type — not even void.
  3. Can take parameters.
  4. Can be overloaded.
  5. Can use any access modifier.
  6. If no constructor is defined, Java provides a default no-argument constructor.
  7. If any constructor is defined, the default is no longer provided.
  8. Constructors are not inherited.

Constructor vs Method

AspectConstructorMethod
NameSame as classAny valid identifier
Return typeNoneRequired
CalledAutomatically on newExplicitly
PurposeInitialize objectPerform behaviour
Constructors

Default Constructor

Two Meanings

  1. The no-argument constructor Java provides automatically if you write none.
  2. Any no-argument constructor you write yourself.

Compiler-Provided

public class Student {
    String name;
    int rollNo;
}

// Equivalent to:
public class Student {
    String name;
    int rollNo;

    public Student() { }
}

Important Rule

If you define any constructor explicitly, the compiler no longer provides the default one. You must write a no-argument constructor yourself if you need one.

Common Bug

public class Student {
    String name;

    public Student(String n) {
        name = n;
    }
}

// elsewhere:
Student s = new Student();
// compile error: no no-arg constructor
Constructors

Parameterized Constructor

Definition

A constructor that accepts arguments, allowing the caller to set initial values for the object's fields at creation time.

public class Student {
    String name;
    int rollNo;
    double gpa;

    public Student(String name, int rollNo,
                   double gpa) {
        this.name = name;
        this.rollNo = rollNo;
        this.gpa = gpa;
    }
}

Usage

Student s = new Student("Alice", 101, 9.1);
System.out.println(s.name);   // Alice
System.out.println(s.rollNo); // 101
System.out.println(s.gpa);    // 9.1

Why Parameterized Constructors Matter

  • Guarantee an object is fully initialized.
  • Prevent partially constructed objects.
  • Make the class easier to use correctly.
  • Reduce the need for multiple setter calls.

Validation in Constructor

public Student(String name, int rollNo,
               double gpa) {
    if (name == null || name.isEmpty()) {
        throw new IllegalArgumentException(
            "Name required");
    }
    if (rollNo <= 0) {
        throw new IllegalArgumentException(
            "Roll number must be positive");
    }
    if (gpa < 0 || gpa > 10) {
        throw new IllegalArgumentException(
            "GPA must be between 0 and 10");
    }
    this.name = name;
    this.rollNo = rollNo;
    this.gpa = gpa;
}
Constructors

Copy Constructor

Definition

A constructor that takes an object of the same class and copies its fields. Java does not provide a default copy constructor; you must write one.

public class Student {
    private String name;
    private int rollNo;
    private double gpa;

    public Student(String name, int rollNo,
                   double gpa) {
        this.name = name;
        this.rollNo = rollNo;
        this.gpa = gpa;
    }

    // Copy constructor
    public Student(Student other) {
        this.name = other.name;
        this.rollNo = other.rollNo;
        this.gpa = other.gpa;
    }
}

Usage

Student s1 = new Student("Alice", 101, 9.1);
Student s2 = new Student(s1); // copy

System.out.println(s1 == s2);        // false
System.out.println(s1.equals(s2));   // depends on equals

Why Use a Copy Constructor?

  • Create an independent copy of an object.
  • Avoid the problems of reference sharing.
  • Control how copying is performed (shallow vs deep).

Note

A copy constructor creates a new object with a distinct identity. The references are different, but the field values are the same.

Constructors

Shallow Copy vs Deep Copy

Shallow Copy

Copies field values. For reference fields, both objects share the same referenced object.

public class Student {
    String name;
    int[] marks;

    public Student(Student other) {
        this.name = other.name;
        this.marks = other.marks;
        // shares the array
    }
}

Problem: modifying marks in the copy affects the original.

Deep Copy

Recursively copies referenced objects so that the copy is fully independent.

public Student(Student other) {
    this.name = other.name;
    this.marks = new int[other.marks.length];
    System.arraycopy(other.marks, 0,
        this.marks, 0, other.marks.length);
}

Rule of Thumb

  • Immutable fields (String, wrappers): shallow copy is sufficient.
  • Mutable fields (arrays, collections, mutable objects): deep copy is usually required.

Bug Pattern

Student s1 = new Student("A", new int[]{1,2});
Student s2 = new Student(s1); // shallow

s2.marks[0] = 99;
System.out.println(s1.marks[0]); // 99 — unexpected!
Constructors

Constructor Overloading

Definition

Defining multiple constructors with different parameter lists. Java chooses the appropriate one based on the arguments at the call site.

Example — Book

public class Book {
    String title;
    String author;
    double price;

    // 1. No-argument
    public Book() {
        this("Untitled", "Unknown", 0.0);
    }

    // 2. Title only
    public Book(String title) {
        this(title, "Unknown", 0.0);
    }

    // 3. Full
    public Book(String title, String author,
                double price) {
        this.title = title;
        this.author = author;
        this.price = price;
    }
}

Usage

Book b1 = new Book();
Book b2 = new Book("Effective Java");
Book b3 = new Book("Clean Code",
                    "Robert Martin", 799.00);

Rules

  • Must differ in number, type, or order of parameters.
  • Return type is irrelevant (constructors have none).
  • Access modifier alone is not sufficient.
  • The compiler resolves the correct overload at compile time.

Invalid Overloading

public Book(String t) { }
// public Book(String s) { } // error: same signature
// private Book(String t) { } // error: only access differs
Constructors

Constructor Chaining with this(...)

Definition

One constructor calls another constructor of the same class using this(...). It must be the first statement in the constructor body.

Complete Example — Employee

public class Employee {
    private String name;
    private String department;
    private double salary;

    public Employee() {
        this("Unknown", "Unassigned", 0.0);
    }

    public Employee(String name, String department) {
        this(name, department, 30000.0);
    }

    public Employee(String name, String department,
                    double salary) {
        if (name == null || name.isEmpty()) {
            throw new IllegalArgumentException(
                "Name required");
        }
        if (salary < 0) {
            throw new IllegalArgumentException(
                "Salary cannot be negative");
        }
        this.name = name;
        this.department = department;
        this.salary = salary;
    }
}

Why Chain?

  • Centralizes initialization logic in one place.
  • Avoids duplicated validation code.
  • Makes adding new fields easier.
  • Reduces the chance of inconsistent initialization.

Rules

  • this(...) must be the first statement.
  • Only one this(...) call per constructor.
  • Do not create cycles (A calls B, B calls A).
  • Cannot appear together with super(...) in the same constructor.
// Invalid
public Book() {
    title = "X";
    this("Y"); // error: not first
}
Constructors

Private Constructors and Validation

Private Constructors

A private constructor prevents external instantiation. Useful for:

  • Utility classes (all static methods).
  • Singletons.
  • Factory methods.
public final class MathUtil {
    private MathUtil() {
        // prevent instantiation
    }

    public static int square(int n) {
        return n * n;
    }
}

Validation in Constructors

Constructors are the right place to validate inputs and enforce invariants.

public class BankAccount {
    private final String accountNumber;
    private double balance;

    public BankAccount(String accountNumber,
                       double initialBalance) {
        if (accountNumber == null
            || accountNumber.isEmpty()) {
            throw new IllegalArgumentException(
                "Account number required");
        }
        if (initialBalance < 0) {
            throw new IllegalArgumentException(
                "Initial balance cannot be negative");
        }
        this.accountNumber = accountNumber;
        this.balance = initialBalance;
    }
}

Why Validate Here?

If the constructor rejects invalid input, no object can exist in an invalid state. This is the strongest form of invariant enforcement.

The this Keyword

Inside any instance method or constructor, this is a reference to the current object. It disambiguates names, enables chaining, and clarifies intent.

this

Referring to the Current Object

What Is this?

this is an implicit reference to the object on which the method was called. It is available inside every instance method and constructor (but not in static methods).

Implicit vs Explicit

public class Student {
    String name;

    void display() {
        System.out.println(name);
        // same as:
        System.out.println(this.name);
    }
}

public class Demo {

this

Resolving Field / Parameter Name Conflicts

Without this

public class Student {
    String name;

    public Student(String name) {
        name = name; // BUG: parameter to itself
    }
}

// s.name remains null

The parameter name shadows the field name. The assignment does nothing useful.

With this

public class Student {
    String name;

    public Student(String name) {
        this.name = name; // field = parameter
    }
}

this.name refers to the field. name on the right refers to the parameter.

Convention

Use the same name for the parameter as the field. Prefix with this. to disambiguate. This makes constructors and setters readable.

public void setRollNo(int rollNo) {
    this.rollNo = rollNo;
}
this

this — Method Chaining

Returning this

A method can return this to enable method chaining (fluent API).

public class Student {
    private String name;
    private int rollNo;
    private double gpa;

    public Student setName(String name) {
        this.name = name;
        return this;
    }

    public Student setRollNo(int rollNo) {
        this.rollNo = rollNo;
        return this;
    }

    public Student setGpa(double gpa) {
        this.gpa = gpa;
        return this;
    }

    public void display() {
        System.out.println(name + " | " + rollNo
            + " | " + gpa);
    }
}

Usage

Student s = new Student()
    .setName("Alice")
    .setRollNo(101)
    .setGpa(9.1);

s.display();
// Alice | 101 | 9.1

Benefits of Fluent APIs

  • Concise and readable.
  • Combines multiple operations in a single expression.
  • Common in builders and configuration APIs.

Passing this as an Argument

public Student(String name) {
    this.name = name;
    register(this); // pass current object
}

static void register(Student s) {
    System.out.println("Registered: " + s.name);
}
this

this(...) — Constructor Chaining Recap

Calling Another Constructor

this(...) invokes another constructor of the same class. It must be the first statement.

public class Book {
    String title;
    String author;
    double price;

    public Book() {
        this("Untitled", "Unknown", 0.0);
    }

    public Book(String title) {
        this(title, "Unknown", 0.0);
    }

    public Book(String title, String author,
                double price) {
        this.title = title;
        this.author = author;
        this.price = price;
    }
}

Rules

  • Must be the first statement.
  • Only one this(...) call per constructor.
  • Do not create cycles.
  • Cannot appear with super(...) in the same constructor.

Invalid Examples

// 1. Not first statement
public Book() {
    title = "X";
    this("Y"); // error
}

// 2. Recursive
public Book() { this(); } // error

// 3. With super
public Book() {
    super();
    this("X"); // error
}
06

Static Members

Static members belong to the class, not to any object. They provide class-level state and behaviour, and initialize when the class loads.

Static Members

Static Methods

Definition

Methods declared with static. They belong to the class, not to any object.

public class MathUtil {
    public static int square(int n) {
        return n * n;
    }

    public static int max(int a, int b) {
        return (a > b) ? a : b;
    }
}

// Usage — no object needed
int s = MathUtil.square(5); // 25
int m = MathUtil.max(3, 7);   // 7

Rules

  • Can access static fields and static methods.
  • Cannot access instance fields or methods directly.
  • No this inside a static method.
  • Can be called without creating an object.

Compile Error Example

public class Student {
    String name;

    static void printName() {
        System.out.println(name);
        // error: cannot access instance field
    }
}

Classic Example

public static void main(String[] args) { }
// JVM calls main without creating an object
Static Members

Static Blocks and Execution Order

Static Block

A block of code marked with static. Runs exactly once when the class is loaded, before any static method or constructor is called.

public class Config {
    static String appName;
    static int version;

    static {
        appName = "MyApp";
        version = 1;
        System.out.println("Class loaded.");
    }
}

Common Uses

  • Loading configuration once.
  • Initializing complex static data.
  • Registering drivers or handlers.

Complete Execution Order

public class Order {
    static int staticVar = initStatic();
    int instanceVar = initInstance();

    static {
        System.out.println("Static block");
    }

    {
        System.out.println("Instance block");
    }

    public Order() {
        System.out.println("Constructor");
    }

    static int initStatic() {
        System.out.println("Static field");
        return 10;
    }

    int initInstance() {
        System.out.println("Instance field");
        return 20;
    }

    public static void main(String[] args) {
        System.out.println("Main started");
        new Order();
        new Order();
    }
}

07

final & Object Identity

final prevents reassignment and subclassing. Object identity distinguishes one object from another even when their state is identical.

final

Final Variables and Constants

Definition

A final variable can be assigned only once. After assignment, its value cannot be changed.

final int MAX = 100;
MAX = 200; // compile error

Three Forms

  • Local final: inside a method.
  • Instance final: per-object constant.
  • Static final: class-level constant.
public class Circle {
    static final double PI = 3.14159;
    final int radius;

    public Circle(int r) {
        radius = r; // assigned once
    }
}

Initialization Rules for Final Fields

  • At declaration, or
  • In every constructor, or
  • In an instance initializer block.

Final Reference vs Final Object

final int[] arr = {1, 2, 3};
arr[0] = 99; // allowed — contents mutable
arr = new int[5]; // error — reference final

final StringBuilder sb = new StringBuilder("Hi");
sb.append("!"); // allowed
sb = new StringBuilder(); // error

final applies to the reference, not to the object's contents.

Naming Convention

Constants are named in UPPER_SNAKE_CASE.

static final int MAX_SIZE = 1024;
static final String APP_NAME = "MyApp";
final

Final Methods, Classes, and Immutability

Final Methods

A final method cannot be overridden by a subclass.

public class Base {
    public final void coreLogic() {
        // cannot be overridden
    }
}

Final Classes

A final class cannot be extended. Examples: String, Integer, Math.

public final class ImmutablePoint {
    private final int x;
    private final int y;

    public ImmutablePoint(int x, int y) {
        this.x = x;
        this.y = y;
    }
}

Immutability

A class is immutable if its state cannot change after construction.

  • Make the class final.
  • Make all fields private and final.
  • Do not provide setters.
  • Initialize all fields in the constructor.
  • If a field is mutable, return a copy from getters.

Example — Money

public final class Money {
    private final double amount;
    private final String currency;

    public Money(double amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }

    public double getAmount() { return amount; }
    public String getCurrency() { return currency; }

    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException(
                "Currency mismatch");
        }
        return new Money(this.amount + other.amount,
                          this.currency);
    }
}

Key Takeaways

  • A class is a blueprint; an object is an instance.
  • Instance members belong to objects; static members belong to the class.
  • Encapsulation protects invariants through private fields and validated accessors.
  • Constructors initialize objects and can be overloaded and chained.
  • this refers to the current object and resolves naming conflicts.
  • final prevents reassignment, overriding, and extension.
  • Identity (==) and equality (equals()) are different concepts.
