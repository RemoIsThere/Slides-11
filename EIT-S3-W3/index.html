01

Creating Classes

A class is the fundamental unit of design in Java. It bundles data and the operations that act on that data into a single coherent entity.

Creating Classes

Class Declaration

General Form

accessModifier class ClassName {
    // fields (state)
    // constructors
    // methods (behaviour)
}

The simplest class is an empty declaration:

class Empty { }

Naming Rules

  • Must be a valid Java identifier.
  • Cannot be a keyword.
  • Convention: PascalCase (e.g., StudentRecord).
  • File name must match the public class name.

A First Class

public class Student {
    String name;
    int rollNo;
}

This declares a class with two fields. No objects exist yet — the class is only a blueprint.

Class vs File

  • A file may contain multiple classes.
  • Only one may be public.
  • The public class name must match the file name.
  • Non-public classes in the same file are package-private by default.
Creating Classes

Fields (Properties)

What Are Fields?

Fields are variables declared inside a class but outside any method or constructor. They represent the state of an object.

public class Book {
    String title;
    String author;
    double price;
    boolean available;
}

Default Values

Fields are automatically initialized to default values if not explicitly set:

TypeDefault
int, short, byte, long0
float, double0.0
char'\u0000'
booleanfalse
Reference typesnull

Local Variables vs Fields

  • Local variables (inside methods) have no default values.
  • Fields have default values.
  • Local variables must be initialized before use.

Field Declaration Options

private String name;                  // private field
public int rollNo;                    // public field
static final double PI = 3.14159; // constant
static int count;                     // static field

Convention

Make fields private and expose them through public methods (getters/setters). This is encapsulation — covered later this week.

Creating Classes

Methods

What Are Methods?

Methods define the behaviour of an object. They operate on the object's fields and perform actions.

public class Student {
    String name;
    int rollNo;

    // method with no return value
    void display() {
        System.out.println(name + " - " + rollNo);
    }

    // method with return value
    String getName() {
        return name;
    }
}

Method Signature

accessModifier returnType name(params) {
    // body
}
  • accessModifier: public, private, protected, or none.
  • returnType: any type, or void.
  • name: camelCase convention.
  • params: zero or more typed parameters.

Instance Methods

Methods that are not static are instance methods. They can access instance fields directly and must be called on an object.

Student s = new Student();
s.name = "Alice";
s.display();  // called on object s
Creating Classes

Object Creation Using new

Syntax

ClassName reference = new ClassName();

The new operator does four things:

  1. Allocates memory on the heap.
  2. Calls the constructor.
  3. Initializes fields to defaults.
  4. Returns a reference to the new object.

Example

Student s1 = new Student();
s1.name = "Alice";
s1.rollNo = 101;
s1.display(); // Alice - 101

Student s2 = new Student();
s2.name = "Bob";
s2.rollNo = 102;
s2.display(); // Bob - 102

Each Object Has Its Own Copy of Fields

s1 and s2 are distinct objects. Changing s1.name does not affect s2.name.

Reference Semantics

Student a = new Student();
Student b = a;       // b points to same object
b.name = "Zara";
System.out.println(a.name); // Zara

Objects are accessed through references. Assigning one reference to another does not copy the object.

Null Reference

Student s = null;
s.display(); // NullPointerException

public class Student {
    // Fields
    String name;

    double gpa;

    // Method
    void display() {

            + " | GPA: " + gpa);

02

Constructors

A constructor is a special method that runs when an object is created. It is how you guarantee an object starts in a valid state.

Constructors

What Is a Constructor?

Definition

A constructor is a special method that is invoked automatically when an object is created with new. Its job is to initialize the new object's fields.

Rules

  • The name must match the class name exactly.
  • It has no return type — not even void.
  • It can take parameters.
  • It can be overloaded.
  • If you define none, Java provides a default constructor.

Syntax

public class Student {
    String name;

    // constructor
    public Student() {
        name = "Unknown";
    }
}

Constructor vs Method

AspectConstructorMethod
NameSame as classAny
Return typeNoneRequired
CalledAutomatically on newExplicitly
PurposeInitialize objectPerform behaviour
Constructors

Default Constructor

Two Meanings

The term "default constructor" is used in two slightly different senses:

  1. The no-argument constructor that Java provides automatically if you write none.
  2. Any constructor with no parameters that you write yourself.

Compiler-Provided

public class Student {
    String name;
    int rollNo;
}

// Equivalent to:
public class Student {
    String name;
    int rollNo;

    public Student() { }
}

Important Rule

If you define any constructor explicitly, the compiler no longer provides a default one. You must write a no-argument constructor yourself if you need one.

Common Bug

public class Student {
    String name;

    public Student(String n) {
        name = n;
    }
}

// elsewhere:
Student s = new Student();
// compile error: no no-arg constructor
Constructors

Parameterized Constructor

Definition

A constructor that accepts arguments, allowing the caller to set initial values for the object's fields at creation time.

public class Student {
    String name;
    int rollNo;

    public Student(String n, int r) {
        name = n;
        rollNo = r;
    }
}

Usage

Student s = new Student("Alice", 101);
System.out.println(s.name);   // Alice
System.out.println(s.rollNo); // 101

Why Parameterized Constructors Matter

  • Guarantee an object is fully initialized.
  • Prevent partially constructed objects.
  • Make the class easier to use correctly.
  • Reduce the need for multiple setter calls.

Validation Inside Constructor

public Student(String n, int r) {
    if (n == null || n.isEmpty()) {
        throw new IllegalArgumentException(
            "Name cannot be empty");
    }
    if (r <= 0) {
        throw new IllegalArgumentException(
            "Roll number must be positive");
    }
    name = n;
    rollNo = r;
}
Constructors

Constructor Overloading

Definition

Defining multiple constructors with different parameter lists. Java chooses the appropriate one based on the arguments at the call site.

Rules

  • Must differ in number, type, or order of parameters.
  • Return type is irrelevant (constructors have none).
  • The compiler resolves the correct overload at compile time.

Example

public class Book {
    String title;
    String author;
    double price;

    // 1. No-argument
    public Book() {
        this("Untitled", "Unknown", 0.0);
    }

    // 2. Title only
    public Book(String t) {
        this(t, "Unknown", 0.0);
    }

    // 3. Full
    public Book(String t, String a, double p) {
        title = t;
        author = a;
        price = p;
    }
}
Constructors

Constructor Chaining and Best Practices

Chaining with this(...)

One constructor can call another using this(...). It must be the first statement in the constructor body.

public Book() {
    this("Untitled"); // calls Book(String)
}

public Book(String t) {
    this(t, "Unknown", 0.0);
}

Why Chain?

  • Centralizes initialization logic in one place.
  • Avoids duplicated validation code.
  • Makes adding new fields easier.

Best Practices

  • Always initialize all fields in some constructor.
  • Validate parameters in the constructor.
  • Chain constructors so the "full" one is the single source of truth.
  • Prefer parameterized constructors over long sequences of setters.
  • Keep constructors short and free of heavy work.

Common Mistakes

// 1. Calling this() not first
public Book() {
    title = "X";
    this("Y"); // compile error
}

// 2. Recursive chaining
public Book() { this("A"); }
public Book(String t) { this(); } // infinite loop
03

Access Modifiers & Encapsulation

Encapsulation means hiding internal state and exposing only what is necessary. Java gives us private and public to enforce this.

Access Modifiers

private

Definition

private is the most restrictive access level. A private member is accessible only within the class where it is declared.

public class BankAccount {
    private double balance;

    public double getBalance() {
        return balance;
    }
}

What It Prevents

BankAccount acc = new BankAccount();
acc.balance = 1000000;
// compile error: balance has private access

Why Private Fields?

  • Prevents invalid state changes.
  • Allows internal representation to change freely.
  • Enforces invariants (e.g., balance cannot be set arbitrarily).
  • Centralizes validation logic.

Private Methods

Methods can also be private. They are helper routines used only inside the class.

private boolean isValidAmount(double amt) {
    return amt > 0;
}
Access Modifiers

public

Definition

public is the least restrictive access level. A public member is accessible from any class, in any package.

public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}

What Should Be Public?

  • The class itself, if it is part of the public API.
  • Methods intended for external use.
  • Constants that clients need.

What Should Not Be Public?

  • Mutable fields — expose getters/setters instead.
  • Helper methods used only inside the class.
  • Anything that reveals internal implementation.

Rule of Thumb

Start with the most restrictive access that works. Widen only when a concrete need appears. Public API is a contract you must maintain.

Access Modifiers

Basic Encapsulation — Getters and Setters

The Pattern

Fields are private. Access is provided through public getter and setter methods.

public class Student {
    private String name;
    private int rollNo;

    public String getName() {
        return name;
    }

    public void setName(String n) {
        if (n != null && !n.isEmpty()) {
            name = n;
        }
    }

    public int getRollNo() {
        return rollNo;
    }

    public void setRollNo(int r) {
        if (r > 0) {
            rollNo = r;
        }
    }
}

Benefits

  • Validation: setters can reject invalid input.
  • Read-only fields: provide only a getter.
  • Computed properties: getter can calculate.
  • Side effects: setter can log or trigger updates.
  • Future-proofing: internal representation can change.

Naming Convention

getX() for getters, setX() for setters. For boolean fields, use isX() (e.g., isActive()).

Encapsulation in One Sentence

Make state private; expose behaviour. The class owns its data and decides what the outside world may do with it.

04

Instance vs Static

Not everything belongs to an object. Some data and behaviour belong to the class itself. Java marks those with static.

Instance vs Static

Instance Variables

Definition

Instance variables are fields declared without static. Each object gets its own copy.

public class Student {
    String name;    // instance variable
    int rollNo;      // instance variable
}

Per-Object Storage

Student a = new Student();
Student b = new Student();

a.name = "Alice";
b.name = "Bob";

System.out.println(a.name); // Alice
System.out.println(b.name); // Bob

Each object has its own name field.

When to Use Instance Variables

  • The value describes a specific object.
  • Different objects should be able to hold different values.
  • The value changes as the object's state changes.

Access from Methods

Instance methods can access instance variables directly — the compiler implicitly prefixes with this.

void display() {
    System.out.println(name); // this.name
}
Instance vs Static

Static Variables

Definition

Static variables are declared with the static keyword. They belong to the class, not to any object. There is exactly one copy shared by all objects.

public class Student {
    String name;
    static int count = 0;  // shared

    public Student(String n) {
        name = n;
        count++;
    }
}

Usage

Student a = new Student("Alice");
Student b = new Student("Bob");

System.out.println(Student.count); // 2

Common Uses

  • Counters of objects created.
  • Constants shared across all instances.
  • Caches.
  • Configuration values.

Warning

Static variables are not thread-safe by default. Concurrent modification can corrupt shared state. We will cover synchronization in a later unit.

Access

Student.count      // via class (preferred)
a.count            // via object (discouraged)
Instance vs Static

Instance Methods

Definition

Instance methods are non-static methods. They operate on a specific object and can access both instance and static members.

public class BankAccount {
    private double balance;

    public void deposit(double amt) {
        if (amt > 0) balance += amt;
    }

    public double getBalance() {
        return balance;
    }
}

Invocation

BankAccount acc = new BankAccount();
acc.deposit(500);
System.out.println(acc.getBalance());

Implicit this

Inside an instance method, the compiler implicitly uses this to access fields and methods of the current object.

public void deposit(double amt) {
    this.balance += amt;
    // same as balance += amt
}

When to Use Instance Methods

  • The behaviour depends on the object's state.
  • The method modifies the object's fields.
  • The method is conceptually an operation of the object.
Instance vs Static

Static Methods

Definition

Static methods belong to the class, not to any object. They can be called without creating an instance.

public class MathUtil {
    public static int square(int n) {
        return n * n;
    }

    public static int max(int a, int b) {
        return (a > b) ? a : b;
    }
}
int s = MathUtil.square(5); // 25
int m = MathUtil.max(3, 7);   // 7

Rules

  • A static method can access static fields and static methods.
  • A static method cannot access instance fields or instance methods directly.
  • There is no this inside a static method.

Compile Error Example

public class Student {
    String name;
    static void printName() {
        System.out.println(name); // error
    }
}

Classic Example

public static void main(String[] args) { }
// main is static — JVM calls it without an object
Instance vs Static

Static Blocks

Definition

A static block is a block of code marked with static. It runs exactly once when the class is loaded, before any static method or constructor is called.

public class Config {
    static String appName;
    static int version;

    static {
        appName = "MyApp";
        version = 1;
        System.out.println("Class loaded.");
    }
}

Execution Order

  1. Static blocks run first, in order of declaration.
  2. Then static fields are initialized (if not already).
  3. Then static methods become available.
  4. Instance initialization happens when an object is created.

Common Use

  • Loading configuration once.
  • Initializing complex static data.
  • Registering drivers or handlers.
static {
    // Class.forName("com.mysql.jdbc.Driver");
}

Note

Static blocks are less common in modern code. Configuration libraries and dependency injection often replace them.

05

The final Keyword

final means "cannot be changed". Applied to a variable, it becomes a constant. Applied to a method, it cannot be overridden. Applied to a class, it cannot be extended.

final

Final Variables

Definition

A final variable can be assigned only once. After assignment, its value cannot be changed.

final int MAX = 100;
MAX = 200; // compile error

Three Forms

  • Local final: inside a method.
  • Instance final: per-object constant.
  • Static final: class-level constant.
public class Circle {
    static final double PI = 3.14159;
    final int radius;

    public Circle(int r) {
        radius = r; // assigned once
    }
}

Final Fields Must Be Initialized

  • At declaration, or
  • In every constructor, or
  • In an instance initializer block.

Naming Convention

Constants are named in UPPER_SNAKE_CASE.

static final int MAX_SIZE = 1024;
static final String APP_NAME = "MyApp";

Final Reference vs Final Object

final int[] arr = {1, 2, 3};
arr[0] = 99; // allowed — array contents can change
arr = new int[5]; // error — reference is final

final applies to the reference, not to the object's contents.

final

final on Members and Classes

final Methods

A final method cannot be overridden by a subclass. Useful when the behaviour must not be altered.

public class Base {
    public final void coreLogic() {
        // cannot be overridden
    }
}

final Classes

A final class cannot be extended. Examples: String, Integer, Math.

public final class ImmutablePoint {
    private final int x;
    private final int y;
}

Why Make Classes Final?

  • Preserves invariants — no subclass can break them.
  • Enables safe sharing across threads.
  • Clarifies intent: this class is not designed for extension.

Constants in Practice

public class Constants {
    public static final double PI = 3.14159;
    public static final int MAX_USERS = 1000;
    public static final String APP_NAME = "MyApp";
}

public static final is the standard pattern for a shared constant.

06

The this Keyword

Inside any instance method or constructor, this is a reference to the current object. It disambiguates names, enables chaining, and clarifies intent.

this

Referring to the Current Object

What Is this?

this is an implicit reference to the object on which the method was called. It is available inside every instance method and constructor (but not in static methods).

Returning the Current Object

public class Student {
    String name;

    public Student setName(String n) {
        this.name = n;
        return this;  // fluent API
    }
}

// Usage:
Student s = new Student()
    .setName("Alice");

Scope of this

  • Available in instance methods.
  • Available in constructors.
  • Not available in static methods.
  • Not available in static blocks.

Implicit vs Explicit

void display() {
    System.out.println(name);
    // same as: System.out.println(this.name);
}

Use this explicitly when it improves clarity or is required.

this

Resolving Field / Parameter Name Conflicts

Without this

public class Student {
    String name;

    public Student(String name) {
        name = name; // BUG: assigns parameter to itself
    }
}

// s.name remains null

The parameter name shadows the field name. The assignment does nothing useful.

With this

public class Student {
    String name;

    public Student(String name) {
        this.name = name; // field = parameter
    }
}

this.name explicitly refers to the field. name on the right refers to the parameter.

Convention

Use the same name for the parameter as the field. Prefix with this. to disambiguate. This makes constructors and setters readable.

public void setRollNo(int rollNo) {
    this.rollNo = rollNo;
}
this

this(...) — Constructor Chaining

Calling Another Constructor

this(...) invokes another constructor of the same class. It must be the first statement in the constructor body.

public class Book {
    String title;
    String author;
    double price;

    public Book() {
        this("Untitled", "Unknown", 0.0);
    }

    public Book(String t) {
        this(t, "Unknown", 0.0);
    }

    public Book(String t, String a, double p) {
        title = t;
        author = a;
        price = p;
    }
}

Rules

  • this(...) must be the first statement.
  • Only one this(...) call per constructor.
  • Do not create cycles (A calls B, B calls A).

Invalid

public Book() {
    title = "X";
    this("Y"); // compile error
}

Why Chain?

Chaining keeps initialization logic in one place. The "fullest" constructor does the real work; the others delegate to it.

String Class

Basic String Processing Tasks

Reverse a String

public static String reverse(String s) {
    StringBuilder sb = new StringBuilder();
    for (int i = s.length() - 1; i >= 0; i--) {
        sb.append(s.charAt(i));
    }
    return sb.toString();
}

Palindrome Check

public static boolean isPalindrome(String s) {
    int l = 0, r = s.length() - 1;
    while (l < r) {
        if (s.charAt(l) != s.charAt(r)) {
            return false;
        }
        l++; r--;
    }
    return true;
}

Count Vowels

public static int countVowels(String s) {
    int count = 0;
    String vowels = "aeiouAEIOU";
    for (int i = 0; i < s.length(); i++) {
        if (vowels.indexOf(s.charAt(i)) != -1) {
            count++;
        }
    }
    return count;
}

Word Count

public static int wordCount(String s) {
    if (s == null || s.trim().isEmpty()) {
        return 0;
    }
    return s.trim().split("\\s+").length;
}

Note

These small tasks appear frequently in vivas. Practise writing them from memory and reasoning about edge cases (empty strings, null, single characters).

Student Class — Constructors and Encapsulation

Student.java

public class Student {
    private String name;
    private int rollNo;
    private double gpa;

    // No-argument constructor
    public Student() {
        this("Unknown", 0, 0.0);
    }

    // Parameterized constructor
    public Student(String name, int rollNo,
                    double gpa) {
        this.name = name;
        this.rollNo = rollNo;
        this.gpa = gpa;
    }

    // Getters
    public String getName()  { return name; }
    public int getRollNo()   { return rollNo; }
    public double getGpa()  { return gpa; }

    // Setters with validation
    public void setGpa(double gpa) {
        if (gpa >= 0 && gpa <= 10) {
            this.gpa = gpa;
        }
    }

    public void display() {
        System.out.println(name + " | " + rollNo
            + " | GPA: " + gpa);
    }
}

Usage

Student a = new Student("Alice", 101, 9.1);
Student b = new Student();

a.display(); // Alice | 101 | GPA: 9.1
b.display(); // Unknown | 0 | GPA: 0.0

Viva Questions

  • Why are the fields private?
  • What happens if we remove the no-argument constructor?
  • What does this(...) do in the first constructor?
  • Why does setGpa validate its argument?

Book Class — Constructor Overloading

Book.java

public class Book {
    private String title;
    private String author;
    private double price;

    public Book() {
        this("Untitled", "Unknown", 0.0);
    }

    public Book(String title) {
        this(title, "Unknown", 0.0);
    }

    public Book(String title, String author,
                double price) {
        this.title = title;
        this.author = author;
        this.price = price;
    }

    public String getTitle()  { return title; }
    public String getAuthor() { return author; }
    public double getPrice()  { return price; }

    public void printDetails() {
        System.out.printf("%s by %s — Rs.%.2f%n",
            title, author, price);
    }
}

Usage

Book b1 = new Book();
Book b2 = new Book("Effective Java");
Book b3 = new Book("Clean Code",
                    "Robert Martin", 799.00);

b1.printDetails();
b2.printDetails();
b3.printDetails();

Output

Untitled by Unknown — Rs.0.00

BankAccount Class — Invariants and Validation

BankAccount.java

public class BankAccount {
    private final String accountNumber;
    private String holderName;
    private double balance;

    public BankAccount(String accNo, String holder,
                       double initial) {
        if (accNo == null || accNo.isEmpty()) {
            throw new IllegalArgumentException(
                "Account number required");
        }
        if (initial < 0) {
            throw new IllegalArgumentException(
                "Initial balance cannot be negative");
        }
        this.accountNumber = accNo;
        this.holderName = holder;
        this.balance = initial;
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Deposit must be positive");
        }
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Withdrawal must be positive");
        }
        if (amount > balance) {
            throw new IllegalStateException(
                "Insufficient balance");
        }
        balance -= amount;
    }

    public double getBalance() { return balance; }
    public String getAccountNumber() {
        return accountNumber;
    }
}

Usage

BankAccount acc =
    new BankAccount("ACC1001", "Alice", 1000);

acc.deposit(500);
acc.withdraw(200);
System.out.println(acc.getBalance()); // 1300.0

Design Notes

  • accountNumber is final — it never changes.
  • balance is private — external code cannot set it directly.
  • The constructor validates its inputs.
  • Business rules live in the methods, not the caller.

Wrap-Up

Summary and Checklist

Key Takeaways

  • A class bundles fields and methods; an object is an instance.
  • Constructors initialize objects; they share the class name and have no return type.
  • Java provides a default constructor only if you write none.
  • Constructor overloading allows multiple initialization paths.
  • private fields plus public methods implement encapsulation.
  • Instance members belong to objects; static members belong to the class.
  • final prevents reassignment or extension.
  • this refers to the current object and resolves name conflicts.
  • String methods are the foundation of text processing in Java.
