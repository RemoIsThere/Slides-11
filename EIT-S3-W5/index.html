Two Forms of Polymorphism

Compile-Time Polymorphism

Usually achieved through method overloading. The compiler determines which overloaded method matches the argument list. 

void print(int x) {}

void print(String x) {}

Runtime Polymorphism

Achieved through overriding and dynamic binding of instance methods. 

Animal a = new Dog();

a.sound();

Method Overloading

Same method name, different parameter list. 

class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a,
            int b,
            int c) {
        return a + b + c;
    }

    double add(double a,
               double b) {
        return a + b;
    }
}
Changing only the return type is not sufficient to overload a method.
Which change creates a valid overload?
Correct. The parameter list must differ.

Upcasting Objects

A subclass object can be stored in a superclass reference. 

class Animal { }

class Dog
        extends Animal {

    void fetch() {
        System.out.println("Fetching");
    }
}

Dog dog = new Dog();

Animal animal = dog;
Upcasting is safe because every Dog is an Animal.

Downcasting Objects

A superclass reference can be explicitly cast to a subclass reference when the actual object is really that subclass. 

Animal animal =
        new Dog();

Dog dog =
        (Dog) animal;

dog.fetch();
Downcasting requires an explicit cast.
A wrong downcast can throw ClassCastException.

Safe Casting with instanceof

Animal animal =
        new Dog();

if (animal instanceof Dog) {

    Dog dog =

Why use instanceof before a downcast?
Correct. It checks whether the runtime object is compatible with the tested type.

ClassCastException

class Animal { }

class Dog
        extends Animal { }

        extends Animal { }

Animal a =
        new Cat();

Dog d =
        (Dog) a;

Generic Programming

Generic programming allows classes and methods to operate on different types while preserving compile-time type safety.

Reusable

Write the logic once and use it with many types.

Type Safe

Type errors can be detected during compilation.

Readable

The intended type is visible in the code.

Why Generics?

Object value = "Java";

String text =
        (String) value;

Raw Object-based designs often require explicit casts. 

Box<String> box =
        new Box<>();

box.set("Java");

String text = box.get();
Generics shift many type checks from runtime toward compile time.

Generic Class

class Box<T> {

Bounded Generics

A type parameter can be restricted using an upper bound. 

static
<T extends Number>
double square(T value) {

    double n =
        value.doubleValue();

    return n * n;
}

The bound guarantees that T provides the behavior available through Number.

Default Interface Methods

Interfaces can contain default instance methods with implementations. 

interface Vehicle {

    void start();

    default void stop() {
        System.out.println("Vehicle stops");
    }
}

class Car
        implements Vehicle {

    public void start() {
        System.out.println("Car starts");
    }
}
Car automatically receives the default implementation of stop() unless it overrides the method.

class SportsCar

Interface Conflict Resolution

interface A {

    default void show() {
        System.out.println("A");
    }
}

interface B {

    default void show() {
        System.out.println("B");
    }
}

class C
        implements A, B {

    public void show() {
        System.out.println("C");
    }
}
When conflicting default methods exist, the implementing class must resolve the conflict.
