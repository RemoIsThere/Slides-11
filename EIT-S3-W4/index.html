01

Inheritance Fundamentals

Inheritance allows one class to acquire the properties and behaviours of another. It models natural "is-a" relationships and enables code reuse without duplication.

Inheritance

What Is Inheritance?

Definition

Inheritance is a mechanism by which one class (the subclass or child class) acquires the fields and methods of another class (the superclass or parent class).

What the Subclass Inherits

  • Fields (subject to access modifiers).
  • Methods (subject to access modifiers).
  • Nested classes.

What the Subclass Can Do

  • Add new fields and methods.
  • Override inherited methods to change behaviour.
  • Use super to invoke parent behaviour.

The Keyword extends

class Superclass {
    // fields and methods
}

class Subclass extends Superclass {
    // additional fields and methods
}

Terminology

TermMeaning
SuperclassParent, base class
SubclassChild, derived class
extendsKeyword establishing inheritance
is-aThe relationship modelled
Inheritance

The "Is-A" Relationship and Why Inherit

The "Is-A" Test

Inheritance models an is-a relationship. If you can say "X is a Y", inheritance may be appropriate.

  • A Car is a Vehicle.
  • A SavingsAccount is a BankAccount.
  • A Dog is an Animal.

Counter-Example

A Car has an Engine. This is a has-a relationship, which calls for composition, not inheritance.

Why Use Inheritance?

ReasonExplanation
Code reuseCommon members defined once in the parent.
Hierarchy modellingNatural "is-a" relationships.
PolymorphismEnables dynamic method dispatch.
ExtensibilityNew subclasses without modifying existing code.
MaintainabilityChanges to shared behaviour in one place.
Inheritance

Syntax and First Example

Animal.java

class Animal {
    String name;

    void eat() {
        System.out.println(name + " is eating.");
    }

    void sleep() {
        System.out.println(name + " is sleeping.");
    }
}

Dog.java

class Dog extends Animal {
    void bark() {
        System.out.println(name + " is barking.");
    }
}

Main.java

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.name = "Rex";

        d.eat();    // inherited
        d.sleep();  // inherited
        d.bark();   // defined in Dog
    }
}

Output

Rex is eating.
Rex is sleeping.
Rex is barking.

Key Observation

Dog did not declare name, eat(), or sleep(). It inherited them from Animal.

02

Types of Inheritance

Java supports several inheritance structures. The terminology describes the shape of the class hierarchy. Some forms are supported only through interfaces.

Types of Inheritance

Single Inheritance

Definition

One subclass extends one superclass.

    A
    |
    B

Example

class A {
    void display() {
        System.out.println("Class A");
    }
}

class B extends A {
    void show() {
        System.out.println("Class B");
    }
}

Usage

B obj = new B();
obj.display();  // inherited from A
obj.show();     // defined in B

Characteristics

  • Simplest form of inheritance.
  • Establishes a clear parent-child relationship.
  • Subclass inherits all accessible members of the superclass.
  • Foundation for multilevel and hierarchical inheritance.
Types of Inheritance

Multilevel Inheritance

Definition

A subclass becomes the superclass of another class, forming a chain.

    A
    |
    B
    |
    C

Example

class A {
    void methodA() {
        System.out.println("A");
    }
}

class B extends A {
    void methodB() {
        System.out.println("B");
    }
}

class C extends B {
    void methodC() {
        System.out.println("C");
    }
}

Usage

C obj = new C();
obj.methodA(); // inherited from A
obj.methodB(); // inherited from B
obj.methodC(); // defined in C

Transitive Inheritance

C inherits from B, which inherits from A. Therefore C also inherits all accessible members of A.

Caution

Deep inheritance chains can become hard to understand. Prefer shallow hierarchies. If a chain exceeds three or four levels, reconsider the design.

Types of Inheritance

Hierarchical Inheritance

Definition

Multiple subclasses extend the same superclass.

       A
      / \
     B   C

Example

class A {
    void common() {
        System.out.println("Common behaviour");
    }
}

class B extends A {
    void methodB() {
        System.out.println("B");
    }
}

class C extends A {
    void methodC() {
        System.out.println("C");
    }
}

Usage

B b = new B();
b.common();  // inherited from A
b.methodB(); // defined in B

C c = new C();
c.common();  // inherited from A
c.methodC(); // defined in C

Common Use

  • Shapes: Circle, Square, Triangle all extend Shape.
  • Employees: Manager, Developer extend Employee.
  • Accounts: SavingsAccount, CurrentAccount extend BankAccount.
Types of Inheritance

Multiple Inheritance — Java's Approach

Not Supported Through Classes

A class cannot extend more than one superclass.

    A   B
     \ /
      C
// Not allowed in Java
// class C extends A, B { }

Why Not?

The diamond problem: if both A and B define a method with the same signature, which one should C inherit? Java avoids this ambiguity by disallowing multiple inheritance of state through classes.

Supported Through Interfaces

Multiple inheritance of type is achieved through interfaces. A class can implement any number of interfaces.

interface A {
    void methodA();
}

interface B {
    void methodB();
}

class C implements A, B {
    public void methodA() {
        System.out.println("A");
    }
    public void methodB() {
        System.out.println("B");
    }
}
Types of Inheritance

Hybrid Inheritance and Summary

Hybrid Inheritance

A combination of two or more inheritance types.

       A
      / \
     B   C
      \ /
       D

Not supported through classes for the same reason as multiple inheritance.

Approximated via Interfaces

interface A {
    void methodA();
}
interface B extends A {
    void methodB();
}
interface C extends A {
    void methodC();
}
class D implements B, C {
    public void methodA() { }
    public void methodB() { }
    public void methodC() { }
}

Summary Table

TypeClassesInterfaces
SingleYesYes
MultilevelYesYes
HierarchicalYesYes
MultipleNoYes
HybridNoYes

Key Takeaway

Java separates inheritance of state (classes, single only) from inheritance of type (interfaces, multiple allowed).

03

The super Keyword

Inside a subclass, super refers to the immediate superclass. It is used to call superclass constructors, access overridden methods, and access hidden fields.

super

Overview and Constructor Call

What Is super?

super is a reference to the immediate superclass of the current object. It is used for three purposes:

  1. Call a superclass constructor: super(...).
  2. Call a superclass method: super.methodName().
  3. Access a superclass field: super.fieldName.

Availability

  • Available in instance methods.
  • Available in constructors.
  • Not available in static methods or static blocks.

Calling a Superclass Constructor

class Animal {
    String name;

    public Animal(String name) {
        this.name = name;
        System.out.println("Animal constructor");
    }
}

class Dog extends Animal {
    String breed;

    public Dog(String name, String breed) {
        super(name);       // calls Animal(String)
        this.breed = breed;
        System.out.println("Dog constructor");
    }
}

Output

Animal constructor
Dog constructor

Rule

super(...) must be the first statement in the constructor body. If omitted, the compiler inserts super().

super

super.method() and super.field

Accessing a Superclass Method

When a subclass overrides a method, super.methodName() calls the superclass version.

class Animal {
    void sound() {
        System.out.println("Some generic sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        super.sound();  // calls Animal's sound()
        System.out.println("Woof!");
    }
}

Output

Some generic sound
Woof!

Accessing a Superclass Field

When a subclass declares a field with the same name as a superclass field, the subclass field hides the superclass field. super.fieldName accesses the superclass field.

class Parent {
    int value = 10;
}

class Child extends Parent {
    int value = 20;

    void display() {
        System.out.println("Child: " + value);         // 20
        System.out.println("Parent: " + super.value);  // 10
    }
}

Field Hiding vs Method Overriding

Field access is resolved at compile time based on the reference type. Method calls are resolved at runtime based on the object type. This difference is a common source of confusion.

Best Practice

Avoid hiding fields. Use distinct field names to prevent confusion.

Mutual Exclusivity

A constructor cannot contain both this(...) and super(...). Only one can be the first statement.

class B extends A {
    public B() {
        super();  // OK
    }

    public B(int x) {
        this();   // OK — calls B()
        // super(x); // would be compile error
    }
}

Indirect Super Call

this(...) can indirectly lead to a super(...) call through the constructor it delegates to.

Common Compile Error

class Animal {
    public Animal(String name) { }
}

class Dog extends Animal {
    public Dog() {
        // compiler tries super() — not found
    }
}

Fix: explicitly call super("Unknown").

04

Method Overriding

Overriding lets a subclass provide a new implementation for a method it inherited. It is the foundation of runtime polymorphism in Java.

Method Overriding

Definition and Rules

Definition

Method overriding occurs when a subclass provides a new implementation for a method that is already defined in its superclass. The method signature must be the same.

class Animal {
    void sound() {
        System.out.println("Some generic sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Woof!");
    }
}

Dynamic Dispatch

Animal a = new Dog();
a.sound(); // Woof! (runtime decision)

Rules for Overriding

RuleExplanation
Same nameMust match exactly
Same parametersTypes and order must match
Covariant returnSame or subtype
Access modifierCannot be more restrictive
final methodsCannot be overridden
static methodsHidden, not overridden
private methodsNot inherited
ExceptionsCannot throw broader checked exceptions
Method Overriding

@Override and Overriding vs Overloading

The @Override Annotation

Tells the compiler that the method is intended to override a superclass method. If it does not, the compiler produces an error.

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Woof!");
    }
}

Benefits

  • Catches typos in the method signature.
  • Documents intent.
  • Makes code easier to review.
  • Protects against accidental overloading.

Overriding vs Overloading

AspectOverridingOverloading
WhereSubclass overrides superclassSame class, different parameters
SignatureSameDifferent
Return typeSame or covariantCan differ
BindingRuntimeCompile-time
PolymorphismRuntime polymorphismCompile-time polymorphism

Memory Aid

Overriding = same name, same parameters, different class. Overloading = same name, different parameters, same class.

Method Overriding

Overriding toString(), equals(), and hashCode()

toString()

Default returns class name and hash code. Override for a meaningful representation.

class Student {
    String name;
    int rollNo;

    public Student(String name, int rollNo) {
        this.name = name;
        this.rollNo = rollNo;
    }

    @Override
    public String toString() {
        return "Student{name='" + name
            + "', rollNo=" + rollNo + "}";
    }
}

Usage

Student s = new Student("Alice", 101);
System.out.println(s);
// Student{name='Alice', rollNo=101}

equals() and hashCode()

Override both together to maintain the contract: equal objects must have equal hash codes.

import java.util.Objects;

@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass())
        return false;
    Student s = (Student) o;
    return rollNo == s.rollNo
        && Objects.equals(name, s.name);
}

@Override
public int hashCode() {
    return Objects.hash(name, rollNo);
}

The Contract

  • Reflexive, symmetric, transitive, consistent.
  • x.equals(null) is false.
  • Equal objects have equal hash codes.
  • Always override both together.
Method Overriding

class Parent {
    public void display() { }
}

Exception Rules

The overriding method cannot throw broader checked exceptions than the overridden method.

class Parent {
    void read() throws java.io.IOException { }
}

class Child extends Parent {
    @Override
    void read() throws java.io.FileNotFoundException { }
    // narrower — OK
}

Unchecked Exceptions

Runtime exceptions (RuntimeException and its subclasses) are not restricted by overriding rules.

05

Covariant Return Types

An overriding method may return a subtype of the return type declared by the overridden method. This reduces the need for casts and enables more fluent APIs.

Covariant Return Types

Definition and Example

Definition

A covariant return type allows an overriding method to return a subtype of the return type declared in the overridden method. Introduced in Java 5.

class Animal {
    Animal create() {
        return new Animal();
    }
}

class Dog extends Animal {
    @Override
    Dog create() {           // Dog is a subtype of Animal
        return new Dog();
    }
}

Benefit

Dog d = new Dog();
Dog d2 = d.create();  // no cast needed

Valid Example — Number and Integer

class Parent {
    Number getValue() {
        return 0;
    }
}

class Child extends Parent {
    @Override
    Integer getValue() {    // Integer is a subtype of Number
        return 0;
    }
}

Invalid Example

class Parent {
    Integer getValue() { return 0; }
}

class Child extends Parent {
    // Number getValue() { return 0; } // error
    // Number is a supertype, not a subtype
}
Covariant Return Types

Practical Use — Builder Pattern

Example

class Pizza {
    Pizza addCheese() {
        System.out.println("Adding cheese");
        return this;
    }
}

class Margherita extends Pizza {
    @Override
    Margherita addCheese() {     // covariant
        super.addCheese();
        System.out.println("Adding extra mozzarella");
        return this;
    }

    Margherita addBasil() {
        System.out.println("Adding basil");
        return this;
    }
}

Usage — Fluent API

Margherita m = new Margherita()
    .addCheese()
    .addBasil(); // no cast needed

Why This Matters

  • Without covariance, addCheese() would return Pizza.
  • You would need a cast to call addBasil().
  • Covariant return types preserve the subclass type through chained calls.
  • Enables fluent APIs and builder patterns.

Common in the Standard Library

Object.clone() returns Object, but overrides typically return the specific class.

@Override
public Student clone() {
    return new Student(this.name, this.rollNo);
}
06

Abstract Classes

An abstract class is a class that cannot be instantiated. It may contain abstract methods (no body) and concrete methods (with body). It is the base for a hierarchy.

Abstract Classes

Definition and Rules

Definition

An abstract class is declared with the abstract keyword. It cannot be instantiated. It may contain:

  • Abstract methods (no body).
  • Concrete methods (with body).
  • Fields.
  • Constructors.
abstract class Shape {
    String name;

    public Shape(String name) {
        this.name = name;
    }

    abstract double area();   // no body

    void display() {           // concrete
        System.out.println(name + ": " + area());
    }
}

Rules

  • Cannot be instantiated.
  • Can have constructors (called via super).
  • Can have abstract and concrete methods.
  • Can have fields.
  • Subclasses must override all abstract methods or be abstract themselves.
  • Can extend another abstract class.
  • Can implement interfaces.

Compile Error

Shape s = new Shape("S");
// error: Shape is abstract; cannot be instantiated
Abstract Classes

Abstract Methods

Definition

An abstract method has no implementation. It must be overridden by any concrete subclass.

abstract class Animal {
    abstract void sound();
}

Rules

  • Can only be declared in an abstract class.
  • The class must be abstract if it contains at least one abstract method.
  • Subclasses must override all abstract methods or be declared abstract.
  • Cannot be private (subclasses could not override).
  • Cannot be static.
  • Cannot be final.

Concrete Subclass Must Implement

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Woof!");
    }
}

Compile Error

class Cat extends Animal {
    // does not override sound()
}
// error: Cat is not abstract and does not
// override abstract method sound()

Fix

Either override sound() or declare Cat as abstract.

Abstract Classes

Complete Example — Shape Hierarchy

Shape.java

abstract class Shape {
    String name;

    public Shape(String name) {
        this.name = name;
    }

    abstract double area();
    abstract double perimeter();

    @Override
    public String toString() {
        return String.format(
            "%s: area=%.2f, perimeter=%.2f",
            name, area(), perimeter());
    }
}

Circle.java

class Circle extends Shape {
    double radius;

    public Circle(double radius) {
        super("Circle");
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }

    @Override
    double perimeter() {
        return 2 * Math.PI * radius;
    }
}

Rectangle.java

class Rectangle extends Shape {
    double width, height;

    public Rectangle(double width,
                     double height) {
        super("Rectangle");
        this.width = width;
        this.height = height;
    }

    @Override
    double area() {
        return width * height;
    }

    @Override
    double perimeter() {
        return 2 * (width + height);
    }
}

Usage

Shape[] shapes = {
    new Circle(5),
    new Rectangle(4, 6)
};

for (Shape s : shapes) {
    System.out.println(s);
}
Circle: area=78.54, perimeter=31.42
Rectangle: area=24.00, perimeter=20.00

07

Interfaces

An interface defines a contract — a set of methods that implementing classes must provide. Interfaces enable multiple inheritance of type and decouple the contract from the implementation.

Interfaces

Definition and Members

Definition

An interface is a reference type declared with the interface keyword. It defines a set of methods that implementing classes must provide.

interface Drawable {
    void draw();
}

Implementing an Interface

class Circle implements Drawable {
    @Override
    public void draw() {
        System.out.println("Drawing a circle");
    }
}

Interface methods are implicitly public. The implementing class must declare them public.

Members

MemberImplicit modifier
Abstract methodspublic abstract
Constantspublic static final
Default methodspublic default
Static methodspublic static
Private methodsprivate (Java 9+)

Constants in Interfaces

interface Constants {
    double PI = 3.14159;      // public static final
    int MAX_SPEED = 200;
}
Interfaces

Default, Static, and Private Methods

Default Methods (Java 8+)

Provide a concrete implementation in an interface. Allow adding new methods without breaking existing implementations.

interface Vehicle {
    void start();
    void stop();

    default void honk() {
        System.out.println("Beep beep!");
    }
}

Conflict Resolution

If a class implements two interfaces that both define a default method with the same signature, the class must override it.

class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();
        // or B.super.hello()
    }
}

Static Methods (Java 8+)

Belong to the interface, not to implementing classes.

interface MathUtil {
    static int square(int n) {
        return n * n;
    }
}

int result = MathUtil.square(5);

Private Methods (Java 9+)

Helper methods for default and static methods.

interface Logger {
    default void logInfo(String msg) {
        log("INFO", msg);
    }

    private void log(String level, String msg) {
        System.out.println("[" + level + "] " + msg);
    }
}
Interfaces

Multiple Inheritance via Interfaces

A Class Can Implement Many Interfaces

interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("Duck is flying");
    }

    @Override
    public void swim() {
        System.out.println("Duck is swimming");
    }
}

Interface Inheritance

An interface can extend one or more interfaces.

interface A {
    void methodA();
}

interface B {
    void methodB();
}

interface C extends A, B {
    void methodC();
}

Key Point

Interfaces enable multiple inheritance of type without the diamond problem because there is no state to inherit. Only method signatures (and default methods) are inherited.

Interfaces

Complete Example — Payment System

PaymentMethod.java

interface PaymentMethod {
    void pay(double amount);

    default void printReceipt(double amount) {
        System.out.println("Paid: " + amount);
    }
}

CreditCard.java

class CreditCard implements PaymentMethod {
    private String cardNumber;

    public CreditCard(String cardNumber) {
        this.cardNumber = cardNumber;
    }

    @Override
    public void pay(double amount) {
        System.out.println("Paid " + amount
            + " via Credit Card ending "
            + cardNumber.substring(cardNumber.length() - 4));
    }
}

UPI.java

class UPI implements PaymentMethod {
    private String upiId;

    public UPI(String upiId) {
        this.upiId = upiId;
    }

    @Override
    public void pay(double amount) {
        System.out.println("Paid " + amount
            + " via UPI: " + upiId);
    }
}

Usage — Polymorphic Dispatch

PaymentMethod[] methods = {
    new CreditCard("1234567890123456"),
    new UPI("alice@upi")
};

for (PaymentMethod m : methods) {
    m.pay(500);
    m.printReceipt(500);
}

Output

Paid 500.0 via Credit Card ending 3456
Paid: 500.0
Paid 500.0 via UPI: alice@upi
Paid: 500.0

Key Observations

  • The array type is PaymentMethod, not a concrete class.
  • Each object responds to pay() in its own way.
  • printReceipt() is inherited from the interface's default method.
Interfaces

Abstract Class vs Interface — Decision Guide

Use an Abstract Class When

  • Subclasses share state (fields).
  • You need constructors.
  • You want to provide partial implementation.
  • The relationship is clearly "is-a".
  • You need to control access modifiers on methods.

Use an Interface When

  • Unrelated classes need to share a capability.
  • You need multiple inheritance of type.
  • You want to decouple the contract from the implementation.
  • The relationship is "can-do".
  • You need a type that can be implemented by classes already extending something else.

Combined Approach

Use both together: an abstract class for shared state and partial implementation, and an interface for the capability contract.

interface Drawable {
    void draw();
}

abstract class Shape implements Drawable {
    String name;
    abstract double area();
}

class Circle extends Shape {
    double radius;

    public void draw() {
        System.out.println("Drawing circle");
    }

    double area() {
        return Math.PI * radius * radius;
    }
}

Rule of Thumb

Program to an interface, not to an implementation. Use abstract classes for shared code; use interfaces for shared contracts.

Packages & Practical

Packages Across Inheritance and Practical Exercises

Access Across Packages

A subclass in a different package can access protected and public members of the superclass, but not package-private or private members.

// com/example/shapes/Shape.java
package com.example.shapes;

public class Shape {
    protected double area;
    public String name;
    private int id;
    double internal; // package-private
}
// com/example/threeD/Cube.java
package com.example.threeD;

import com.example.shapes.Shape;

public class Cube extends Shape {
    void compute() {
        area = 100;      // OK (protected)
        name = "Cube";   // OK (public)
        // id = 1;       // error (private)
        // internal = 5; // error (package-private)
    }
}

Wrap-Up

Summary and Checklist

Key Takeaways

  • Inheritance models "is-a" relationships and enables code reuse.
  • Java supports single, multilevel, and hierarchical inheritance through classes.
  • Multiple and hybrid inheritance are achieved through interfaces.
  • super refers to the immediate superclass.
  • Method overriding enables runtime polymorphism.
  • Covariant return types allow an overriding method to return a subtype.
  • Abstract classes cannot be instantiated and may contain abstract methods.
  • Interfaces define capability contracts and support multiple inheritance of type.
  • Packages organize code and prevent naming conflicts.
